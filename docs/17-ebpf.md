# 17. eBPF / TUN-TAP: уровень ядра (экспериментальный этап)

> eBPF/TUN-TAP — **самый экспериментальный и отложенный этап** (6 по [08-development.md](08-development.md)), доступен только на Linux под root/CAP_NET_ADMIN. Базовый вариант обходится без него кросс-платформенным `socket2`. Здесь — карта для исследования.

## 17.1. Зачем

Продвинутые антиботы анализируют **не только TLS, но и TCP-пакеты на уровне ядра**: MTU, Window Size, TTL, последовательность RST/FIN. Правильный ответ — подменить параметры TCP-стека под эмулируемую ОС, а не эмулировать в user-space.

## 17.2. Вариант на user-space (без root)

Есть кросс-платформенный способ — `socket2` настраивает:
- TCP window size / MTU / NODELAY для сокета;
- TCP keep-alive параметры;
- mark для ip правила (Linux `SO_MARK`).

Это достаточная база для большинства сценариев и **работает без root** — планируется в Фазу B (см. [02-stealth.md](02-stealth.md#25-поведенческие-фишки-behavioral-anti-detection)).

> **Статус:** план (зависимость `socket2` пока не входит в стек).

## 17.3. Вариант с eBPF (root, Linux only)

| Компонент | Назначение |
|---|---|
| **kprobes/tracepoints** на `ip_local_out`/`tcp_{v4,v6}_init` | перехват и модификация TCP-параметров (Window, MSS, SACK) под нужную ОС |
| **TC-bpf** (tc egress/ingress) | подмена/распределение TTL, времени ответа |
| **XDP-программа** | ручное построение заголовков IP на входе |

**Сложность:** eBPF требует `bpf` syscall, полного контекста ядра, загрузки программ через `libbpf`/`aya` (pure-Rust). Ошибка ведёт к сбою на уровне ядра — крайне аккуратно.

## 17.4. Вариант с TUN/TAP (root, Linux)

Создание виртуального сетевого интерфейса; весь трафик перенаправляется в user-space, где мы сами формируем пакеты. Даёт полный контроль, но:
- высокая нагрузка на CPU (каждый пакет проходит через user-space);
- сложный management (маршруты, против шума);
- полезен скорее для исследовательских прототипов, чем для прод.

## 17.5. Рекомендуемая стратегия

1. **Начинать с `socket2`** (см. [02-stealth.md](02-stealth.md#25-поведенческие-фишки-behavioral-anti-detection)) — кросс-платформенно, no-root, и покрыто юнит-тестами.
2. **Исследовать eBPF-поход под Linux**, если socket2-уровня окажется недостаточно для конкретного антибота (начиная с `aya` — pure-Rust).
3. **TUN/TAP** — только как исследовательский стенд, не в прод.

## 17.6. Чек-лист (флаг `ebpf`)

- [ ] Реализация только под `cfg(target_os = "linux")`, включение только фича-флагом `ebpf`.
- [ ] Полный фоллбэк на `socket2`-реализацию, если eBPF недоступен (нет root/провайдер).
- [ ] Загрузка eBPF-программ только через `aya`/`libbpf-rs` (pure-Rust), без Socket-фрагментации.
- [ ] Юнит-тесты на формирование пакетов без реального root.
- [ ] No-op если интерфейс недоступен — воркер не падает, а работает на socket2.
