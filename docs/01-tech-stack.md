# 1. Технологический стек и ключевые фичи

## 1.1. Сетевой уровень (имперсонация)

### `rquest` / `reqwest-impersonate`
Сетевые клиенты на базе **BoringSSL** (от Google) для 100% маскировки сетевых отпечатков под реальные браузеры — **Chrome, Safari, Firefox**. Маскируются:
- TLS-отпечаток **JA4** (ранее JA3);
- HTTP/2 фреймы (SETTINGS, WINDOW_UPDATE, PRIORITY);
- порядок и регистр заголовков.

### `tokio`
Асинхронный рантайм для параллельной обработки сотен потоков и сетевых запросов одновременно.

## 1.2. Слой автоматизации и JS-рантайм (собственный движок)

> Мы **не внедряем** готовый браузер. Движок собирается из своих специализированных крейтов (подробнее — [11-browser-engines.md](11-browser-engines.md)).

### `boa_engine`
JavaScript-движок на чистом Rust — узкий JS-рантайм для изоляции и выполнения скриптов защиты (Cloudflare, Akamai) **без утечки реальных метаданных системы**. Аналог headless-браузера для JS-части, но без всего лишнего.

### `html5ever` / `scraper`
Быстрые pure-Rust парсеры для построения виртуального DOM-дерева в памяти и поиска элементов по **CSS-селекторам / XPath**.

### `arachne-stream`
Собственный крейт стриминга: lock-free очереди, backpressure и конвейерная обработка данных (см. [18-distributed.md](18-distributed.md#184-локфри-структуры-данных))

## 1.3. Управление данными и сценариями

### `serde` / `serde_json` / `serde_yaml`
Сериализация и десериализация пользовательских макросов и конфигураций сессий.

### `cookie` / `cookie_store`
Единое потокобезопасное хранилище cookie-файлов для сквозной авторизации.

## 1.4. Веб-слой и SaaS (перспектива)

Перспективный SaaS-слой строится на `axum` (REST API/аутентификация/биллинг) + `leptos` (SSR+CSR для low-code конструктора сценариев из блоков). Мультитенантность, оплата по подписке/запросу и резидентные прокси как сервис — детально в [19-saas-platform.md](19-saas-platform.md). Не входит в базовое ядро (подключается за фича-флагом `saas`).

## 2. Ключевые фичи комбайна

### 2.1. Двухрежимная архитектура (Hybrid Core)
На лету переключает сессию между:
- **сверхбыстрым HTTP-режимом** — для парсинга API и статического HTML;
- **браузерным режимом** — для эмуляции действий пользователя.

### 2.2. Синхронизация сессий (Cookie-Jar Sharing)
Единое сквозное хранилище **Cookie и LocalStorage**. Авторизация, пройденная в HTTP-клиенте, мгновенно доступна в собственном JS/DOM-движке, и наоборот.

### 2.3. Эмуляция сетевого уровня (Stealth TLS/H2)
Автоматическая генерация валидных **Client Hello** пакетов, соответствующих выбранному User-Agent. Исключает бан по отпечаткам **JA3/JA4**.

### 2.4. Полифилы маскировки (Anti-Fingerprinting JS)
Встроенная подмена глобальных JS-объектов (`window`, `navigator`, `screen`):
- скрытие флага `navigator.webdriver`;
- подмена установленных плагинов;
- подмена аппаратных характеристик.

### 2.5. Интерпретатор макросов действий
Движок, читающий JSON/YAML-сценарии и эмулирующий реальное поведение человека:
- клики, ввод текста, скроллинг;
- движение мыши по кривым **Безье**;
- случайные задержки по распределению **Гаусса**.

### 2.6. Изолированная многопоточность
Каждый JS-контекст `boa_engine` запускается в **чистом изолированном пуле памяти**, что предотвращает утечки ресурсов при долгой работе. Передача данных между контекстами — через lock-free очереди `arachne-stream` (без блокирующих мьютексов).

### 2.7. Встроенная ротация прокси
Поддержка **SOCKS5/HTTP** прокси на уровне отдельных запросов или вкладок с автоматическим обновлением цепочки адресов.

> Подробнее про стелс-фичи и обход защит — в [02-stealth.md](02-stealth.md).
