# 11. Пишем свой модульный движок (а не внедряем чужой браузер)

> **Решение принято:** мы **не внедряем** в проект ни готовый полноценный браузер (Chromium, Servo, BrowserOxide), ни готовый headless-движок (Obscura и т.п.). Комбайн собирается **из своих специализированных крейтов** для максимальной гибкости и кастомизации. Готовые движки — только **референс для изучения решений**, в зависимость не тянутся.

## 11.1. Почему свой модульный проект

1. **Максимальная гибкость.** Мы контролируем **каждый байт** от TCP-сокета до JS-фрейма. Чужой движок диктует свои представления о DOM, сессиях и фингерпринтах — подгоняя Smart Router под него, мы теряем гибкость.
2. **Полная кастомизация фингерпринтов.** Нативный стелс (см. [02-stealth.md](02-stealth.md#22-нативный-стелс-на-уровне-rust-компиляции)) проще сделать на своём стеке, чем «оборачивать» чужой.
3. **Тонкий Fast HTTP.** Для большинства задач нужен только быстрый парсинг без JS/DOM-стека. Чужой движок тянет всё целиком; свои крейты собираются точечно под задачу.
4. **Никаких чужих представлений о сессиях.** Единый `StealthSession` ([04-architecture.md](04-architecture.md)) — наш, а не адаптер поверх чужого API.
5. **Долгосрочная перспектива.** Свой бесшовный движок проще переносить в многопоточный / мультинодный режим (см. [18-distributed.md](18-distributed.md)).

## 11.2. Из чего собираем (все крейты — свои)

```
arachne/
├── arachne-core/         # домен: Newtype-типы, ошибки, конфиг, сценарии
├── arachne-net/          # транспорт: rquest, имперсонация, ротация прокси
├── arachne-dom/          # парсинг: html5ever + scraper, CSS/XPath поиск
├── arachne-js/           # JS-рантайм: boa_engine, нативные биндинги фингерпринтов
├── arachne-stealth/      # маскировка: BrowserForge-профили, полифилы, jitter
├── arachne-router/       # Smart Router: выбор режима, эскалация
├── arachne-macro/        # интерпретатор YAML/JSON-макросов
├── arachne-stream/       # стриминг данных, backpressure, lock-free очереди
├── arachne-observ/       # tracing-спаны, state dumps
└── arachne (bin)         # CLI: склейка
```

**Жёсткое правило:** каждый компонент — отдельный крейт с узкой ответственностью. Замена транспортного клиента (`rquest` → другой) — это правка одного адаптера внутри `arachne-net`, остальной код не трогается.

## 11.3. Роль готовых движков — только референс

| Движок | Роль в проекте |
|---|---|
| **BrowserOxide** (`browser_oxide`) | **Референс, не зависимость**: изучаем, как делаются нативные фингерпринты и структура DOM. В `Cargo.toml` **не включаем**. |
| **Obscura** | Источник практик по изоляции страниц и `--stealth`-режиму, без прямой зависимости. |
| **boa_engine** | **Используем** — это не «браузер», а узкий JS-рантайм (EcmaScript), компонент `arachne-js`. |
| **html5ever / scraper** | **Используем** — узкие парсеры HTML/DOM, компонент `arachne-dom`. |
| **Servo** | Избыточен (полный движок с `mozjs`), в проект не попадает. |

## 11.4. Что берём из чужих движков (а не их код)

- **Нативные фингерпринты вместо JS-инъекций** — архитектурный подход BrowserOxide, воспроизводим на своём стеке через Rust-биндинги `boa_engine` (см. [05-rust-patterns.md](05-rust-patterns.md#56-нативные-rust-биндинги-к-js-вместо-инъекций)).
- **Изоляция контекстов страниц** — логика из Obscura, см. [04-architecture.md](04-architecture.md#43-изолированная-многопоточность).
- **Потоки/конвейеры обработки** — паттерны из Spider/recluse, адаптируем через стриминг и lock-free очереди (см. [18-distributed.md](18-distributed.md#184-локфри-структуры-данных)).

## 11.5. Чек-лист «не внедряем чужой браузер»

- [ ] В `Cargo.toml` **нет** зависимостей вида `browser_oxide`, `servo`, `obscura`, `chromium-*`, `CDP`, `headless-engine`/`oxibrowser` как внешнего движка.
- [ ] `html5ever`/`scraper`/`boa_engine` — только как узкие компоненты, а не «браузер».
- [ ] Нативный стелс реализован нашими Rust-биндингами, а не инъекциями и не чужим движком.
- [ ] Любая «динамика страниц» собирается из своих крейтов (DOM + JS + стриминг), без внешних процессов.
