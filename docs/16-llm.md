# 16. LLM-интеграции (Отдельный / поздний этап)

> LLM здесь — **не** «умный обходчик» вообще, а узкие специализированные модули: выбор селекторов по скриншоту и решение визуальных капч локально (без внешних API). Подключается **в последнюю очередь** (этап 6, [08-development.md](08-development.md)) и только под фича-флагом `llm`. Базовый вариант работает без неё.

## 16.1. LLM-Vision селекторы

Проблема: классические селекторы (CSS/XPath) хрупкие — сайт перекрасили или изменили класс, макрос ломается.

**Решение:** `arachne-llm` берёт **скриншот живой вкладки** (из собственного движка) и по запросу нейросети возвращает:
- координаты элемента (баундинг-бокс);
- предлагаемый устойчивый селектор (например, ближайший `[data-testid]` или текст-якорь).

Результат — **не жёсткий селектор**, а семантика «найди кнопку «Купить»», что резко повышает живучесть макросов.

## 16.2. Локальное решение визуальных капч (ONNX)

Anti-captcha-saas заменяется локальной моделью:
- **Пайплайн**: `onnxruntime` + заранее обученная сетка (разделённая на детектор сегментов и классификатор);
- **В-продакшн**: никаких внешних CDN-кадров, модель качается один раз и загружается в память;
- **Профиль трафика**: решение капчи не уходит во внешний сервис = меньше утечек фингерпринтов, точнее тайминги.

## 16.3. Эвристические «human-challenge`» трансляции

Нейросеть-эвристика подсказывает, как сейчас выглядит защита: если в DOM виден `<iframe id="cf-chl-*">` или при `document.cookie` нет `cf_clearance` — логика карты действия подсказывает await-эскалацию в Headless и проверку по [03-smart-routing.md](03-smart-routing.md).

## 16.4. Управление памятью LLM-работников

LLM (ONNX) — тяжёлый в RAM. Правила разделения ресурсов:
- выделенный поток/задача для инференса (не в сетевом runtime);
- жёсткий лимит RAM на LLM-контекст (правило «40 МБ на контекст», см. [04-architecture.md](04-architecture.md#44-защита-от-oom));
- кэширование результатов `(скриншот_хэш → селектор)`, чтобы не гонять модель впустую.

## 16.5. Чек-лист LLM-этапа

- [ ] `onnxruntime` включён **только** за фича-флагом `llm` (не в базовый bul dimens апшип).
- [ ] Разделены «детектор капч» и «селектор-Vision» как два загружаемых модуля.
- [ ] Инференс и сетевой обмен не блокируют друг друга (`spawn_blocking` для ONNX).
- [ ] Кэш `screen_hash → selector` включён, лимит RAM соблюдается.
- [ ] Все вызовы — через трейт `VisionBackend` — можно менять бэкенд без правки роутера.
